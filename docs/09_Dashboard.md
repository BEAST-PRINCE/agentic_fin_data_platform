# 09 - Dashboard

The backend of this project is a complex web of Kafka, Spark, DuckDB, and AI agents. But to the end-user, none of that matters. They just want a clean interface where they can ask a question and get an answer.

I built the Dashboard using React to be the single pane of glass for the entire Agentic Datalake.

## ⚛️ React Architecture

I chose React with Vite for fast local development and for managing the dashboard's operational views. The current application uses REST requests and polling rather than streaming agent responses.

The application is structured into a few core components:
* **The Main Layout:** Handles navigation and persistent sidebar elements.
* **The Chat View:** The primary interaction zone. It renders Markdown natively, so the tables and bullet points generated by the Synthesizer agent look beautiful.
* **The Workflow Accordion:** This is my favorite feature (more on this below).
* **The Metrics Panel:** A high-level overview of Lakehouse stats (e.g., "Total Articles Ingested Today").

## 🕵️‍♂️ The Agent Workflow Viewer

One of the biggest problems with AI applications is that they act like black boxes. You ask a question, you wait 30 seconds, and you get an answer. You have no idea if the AI actually checked a database or just hallucinated the response.

I solved this by building the **Agent Workflow Accordion**.

When you ask a question, the dashboard shows a loading state and then renders the completed workflow steps returned by `/api/chat/multi`:
1. `[+] Planner` ➔ *Shows the parsed plan summary.*
2. `[+] Researcher` ➔ *Shows counts and returned evidence details when available.*
3. `[+] Summarizer` and `[+] Analyst` ➔ *Show their parsed intermediate packages.*

This creates absolute transparency. If the final answer looks weird, you can open the accordion, see exactly which tool the Researcher used, and realize it pulled data for the wrong date range. It turns debugging from a nightmare into a UI feature.

## 🔌 API Integration & State Management

The dashboard communicates heavily with the FastAPI backend (`src/serving/`).
* **State:** I use standard React hooks (`useState`, `useEffect`) to manage the chat history and the loading states of the agent workflow.
* **Polling:** Status and log panels poll REST endpoints on intervals. Chat requests wait for the complete JSON response; there is currently no SSE, WebSocket, or token-by-token response stream.

## 🎨 UI Decisions

I leaned into a modern, slightly "hacker" aesthetic. 
* **Dark Mode Default:** Because staring at bright white screens while analyzing data is exhausting.
* **Typography:** Clean, monospaced fonts for data tables to ensure numbers align properly, paired with highly readable sans-serif fonts for the generated reports.
* **Color Coding:** The workflow viewer uses specific colors for different agents (e.g., Blue for Planner, Green for Researcher) so you can visually track who is doing what at a glance.
