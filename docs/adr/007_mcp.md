# ADR 007: Using Model Context Protocol (MCP)

**Status:** Accepted  
**Date:** July 2026  

## 📜 Context and Problem Statement
LLMs are locked in a box. They only know their training data. To make an AI agent useful in a Datalake, it must be able to execute database queries.

Historically, this meant writing custom "Tool Call" schemas specifically tailored to OpenAI's API, or using LangChain `@tool` decorators. The problem is that if you want to switch from OpenAI to Anthropic, or from a hosted model to a local Llama 3 model, you often have to rewrite how your tools are parsed and executed because every LLM provider expects slightly different JSON formats for function calling.

I needed a standardized, universal way for *any* LLM to request data from my FastAPI backend.

## 🤔 Considered Options
1. **LangChain `@tool` Decorators:** Easy to write in Python, but tightly couples the database logic directly to the agent orchestration code.
2. **OpenAI Custom Functions:** Locks the entire project into the OpenAI ecosystem.
3. **Model Context Protocol (MCP):** An open standard designed specifically to decouple AI models from data sources.

## ✅ Decision
I chose the **Model Context Protocol (MCP)** to expose the Datalake to the AI agents.

The data retrieval logic (querying DuckDB and Qdrant) is wrapped in a standalone MCP Server running over `stdio` (`src/serving/mcp/server.py`). 

The Agent Orchestrator connects to this server. The MCP server automatically broadcasts its available tools (`retrieve_articles`, `get_daily_trends`, etc.) and their strict JSON schemas to the agent. When the agent wants to use a tool, it sends a JSON-RPC request to the server, and the server returns the raw string data.

## 📈 Consequences
* **Positive:** Absolute decoupling. The FastAPI developers can add new database tables and expose them via MCP without ever touching the Agent Orchestrator code.
* **Positive:** Universal compatibility. Because MCP is an open standard, any LLM that supports MCP can act as the "Researcher" agent without rewriting the tool definitions.
* **Negative:** MCP over `stdio` relies heavily on standard output. As documented in the Troubleshooting guide, this required writing complex OS-level file descriptor redirects to prevent C-level libraries (like PyTorch) from printing warnings and corrupting the JSON communication pipe.
